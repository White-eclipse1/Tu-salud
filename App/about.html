Proyecto Academico - Machine Learning Medico

Acerca de
Tu Salud

Sistema web que conecta una interfaz clinica con modelos entrenados para analizar perfiles K-Means y predicciones supervisadas de riesgo medico.

Que hace el proyecto

Tu Salud permite capturar datos clinicos de un paciente y enviarlos a un backend local hecho con FastAPI. El backend carga modelos guardados con joblib desde la carpeta models/ y devuelve resultados para diabetes, hipertension arterial, paro cardiaco y una evaluacion general.

El flujo actual usa primero el modelo no supervisado K-Means para ubicar al paciente dentro de grupos clinicos reales guardados en los metadatos. Despues ejecuta los modelos supervisados y compara si el grupo asignado tiene relacion con las probabilidades individuales.

!

Aviso: los resultados son generados por modelos entrenados para fines academicos. No sustituyen una valoracion medica, no constituyen diagnostico y deben interpretarse solo como apoyo experimental.

No supervisado

K-Means exploratorio

El modelo no supervisado se usa para asignar al paciente a un grupo clinico segun la cercania a los centroides aprendidos.

  • Diabetes: 2 clusters, silhouette 0.196
  • Hipertension: perfiles K-Means exploratorios, silhouette aprox. 0.301
  • Paro cardiaco: perfiles K-Means exploratorios, silhouette aprox. 0.225
  • Se muestran datos descriptivos: perfil asignado, distancia al centroide, n del grupo y referencia posterior del modelo supervisado.

Silhouette mide que tan separados estan los clusters: valores cercanos a 1 indican grupos muy definidos, valores cercanos a 0 indican grupos mezclados. En este proyecto se interpreta como referencia exploratoria, no como diagnostico.

Supervisado

Modelos de prediccion

El backend ejecuta clasificadores entrenados y devuelve porcentajes de riesgo por condicion.

  • Diabetes usa variables tipo Pima: glucosa, presion diastolica, insulina, IMC, edad y antecedentes.
  • Hipertension usa biomarcadores, antropometria, presion, actividad y variables metabolicas.
  • Paro cardiaco usa edad, sexo, frecuencia cardiaca, presion, glucosa, CK-MB y troponina.
API
Arquitectura del sistema
Frontend estatico, backend FastAPI y modelos joblib

La aplicacion funciona como una integracion local. El usuario abre el frontend en App/index.html, levanta el backend con Uvicorn y el navegador consume los endpoints en http://localhost:8000.

Backend

Endpoints disponibles

  • GET /health: confirma que la API esta activa.
  • POST /cluster: ejecuta K-Means y devuelve el perfil exploratorio asignado por dataset.
  • POST /predict: ejecuta modelos supervisados y devuelve porcentajes de riesgo.
Frontend

Interfaz de analisis

  • Formulario con los campos que esperan los modelos reales.
  • Resumen K-Means antes de la prediccion supervisada.
  • Comparacion entre referencia del perfil y prediccion individual.
  • Diseno visual actualizado a estilo de software medico.

Artefactos

Modelos guardados

La carpeta models/ concentra los archivos usados en produccion local:

  • diabetes_model.joblib y diabetes_metadata.json
  • hipertension_model.joblib, scaler y metadata
  • paro_cardiaco_model.joblib, scaler y metadata
  • subtipos_kmeans.joblib y subtipos_metadata.json
Datos de entrada

Variables solicitadas

El formulario pide campos compartidos y especificos para que todos los modelos puedan funcionar.

  • Datos generales: edad, sexo, IMC, glucosa y presion arterial.
  • Diabetes: embarazos, pliegue cutaneo, insulina y funcion pedigree.
  • Cardiaco: frecuencia cardiaca, glucosa, CK-MB y troponina.
  • Hipertension: biomarcadores, colesterol, antropometria, sueno y actividad.

Consideraciones
  • Los perfiles muestran datos guardados: n, referencia descriptiva y distancia al centroide.
  • No se dibujan nubes de pacientes porque el joblib no guarda los puntos originales.
  • Para graficas PCA reales se tendrian que guardar coordenadas o muestras del entrenamiento.
  • La API debe estar encendida para que el frontend genere resultados.
